# 救助留言中的个体辨认与寄养交接

溪坞志愿站使用虚构的动物档案、群聊和交接。chip 是档案内的虚构识别码，null 代表该条记录没有芯片观测。verifyRole 标明某类文字的记录来源，仍应保留一手亲见和转述的差别。演练资料涵盖已预约及已完成的交接。

## 本地资料

全部为 UTF-8 编码的合成业务资料。`data/contract.json` 中的列类型带 `?` 时可以是 JSON null。每组记录的 `id` 在该组中唯一，跨组关系以字段说明和清单的 `links` 为准。文字字段保留来源原句，嵌套对象按表中现有格式记录。

- `data/animals.json`。登记时的个体资料。aliases 不是唯一身份，place 表示当次登记的观察地点。
- `data/locations.json`。虚构夜间安置点与家庭接送范围。capacity 是地点的同时名额。
- `data/messages.json`。值班留言。sender 是虚构代号，replies 为实际引用或回复。text 不预填识别结果。
- `data/handoffs.json`。实际留档的预约或交接。assigned 为当时使用的档案编号，mayInclude 代表当时交接单仍需核实的候选，不是许可。

## 使用约定

短期预约限制开始与交回日期，长期安置持续占位直到有明确交回。家庭有条件相容时才算可用地点，预约期间也占相应名额。照护人员留言的个人意见与实际作出的预约分开。对同住约束若无法确认程度，从原见证和正式确认中补问，不擅自拆组或强制将两只作为同一对象。站医记录是离开隔离的许可来源，只能用于指定个体、交接方向和时间窗口。已交接后的跟踪是另一条事实。

## 读取与检查

使用 Node.js 22.23.4，依赖仅用 Node.js 标准库。资料检查依次读入各组 JSON，检查列类型、组内编号及已登记的组间引用，并列出各组记录数。读取入口为 `tools/materials.mjs`，可单独读取一组记录，或读取整个已登记资料包。

```sh
npm run check-data
npm test
```

## 留言判读与值班视图

`src/` 下的模块把线上留言整理成值班人可直接处理的形式，规则是透明的关键字规则，只覆盖本演练语料的表达；拿不准的一律标“待核”，不擅自定身份。

- `src/identity.mjs`。称呼、芯片、外貌、地点到档案候选的映射。aliases 只产生候选集，place 只作弱证据，芯片与外貌才是强证据。
- `src/intake.mjs`。每条留言拆成单主体主张：谁亲眼见到（亲见 / 转述 / 当事人 / 核验 / 值班确认 / 条件声明）、哪只、哪个地点、什么时间、哪个照护阶段。更正留言逐条覆盖被回复留言中同个体、同阶段、极性相反的状态主张，原主张保留并标记“被更正”。
- `src/clearance.mjs`。站医许可只覆盖说清的个体、交接方向与时间窗口；明确的拒绝同样只针对所指个体。
- `src/constraints.mjs`。同伴关系分级（必须同运 / 可分养但领养须同户 / 仅同来可分开）与接收方家庭开出的条件（期限、只数、离隔确认、隐私等）。
- `src/briefing.mjs`。汇总成值班视图：可核实的安排、仍缺的确认、已发生的交接、可接手的原留言。核实请求支持合并 / 拆开 / 继续待核：拆开时许可不复制给另一只、伙伴的已预约安排不动；芯片不同的档案拒绝合并。已交接记录只允许另建待确认的回访或转介，历史不写成未离开。`familyNotice` 生成对外给家庭看的安排，只含本次必要照护指示；`placementOptions` 按名额、隔离容量与家庭承诺评估去向。

```sh
npm run briefing                 # 值班视图
node tools/briefing.mjs notice h1        # 对外家庭通知
node tools/briefing.mjs decide v1 拆开   # 演示核实决定
node tools/briefing.mjs options A3       # 某只个体的去向评估
```
